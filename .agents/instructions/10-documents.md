# Documents

Read before editing `README.md`, a primary reference, or `.readme/`, and before closing a change that altered a fact one of them owns.

- Update only the owner of each changed fact: product intent in `.docs/product.md`, observable design in `.docs/design.md`, the stack in `.docs/stack.md`, technical direction and status in `.docs/plan.md`, pending work in `.docs/backlog.md`, coverage in `.docs/coverage.md`, defects in `.docs/bugs.md`, security and maintenance evidence in `.docs/security.md`, public usage in `README.md`, and detailed operation in `.readme/`.
- Keep one authoritative home per fact and link or summarize it elsewhere; when code, schema, or configuration enforces a fact, state the decision and name that source instead of copying what it holds.
- Keep `.docs/product.md` to platform, users, purpose, positioning, context, capabilities, constraints, brand commitments, principles, accessibility needs, scope, actors, permissions, journeys, rules, invariants, data sources, integrations, data classifications, public contracts, terminology, success criteria, and risks; an undelivered capability keeps its definition there and its detail in `.docs/backlog.md`.
- Keep `.docs/design.md` to normative tokens, intended experience, visual and interaction rules, voice, accessibility, supported states, and observable acceptance criteria.
- Write `.docs/plan.md` at decision level, each decision with the constraint that forced it and the source that enforces it, covering direction other than the stack, ownership, delivered phases, validation strategy, configuration, observability, recovery, accepted non-security risks, verified status, and acceptance evidence, without identifiers, fields, signatures, routes, versions, or configuration values.
- Keep `.docs/coverage.md` to the last complete verified run, the coverage threshold's source, coverage per requirement or journey, and completed manual or agent-operated verifications, never individual tests; update it when a change affects a requirement or journey.
- Keep `.docs/bugs.md` to the register its schema defines: record or update the stable record of a confirmed defect in delivered behavior found during an authorized change, link it with its regression test both ways, and keep its security impact in its row and the vulnerability's state in the linked `.docs/security.md` entry; for a diagnosis-only request, report the update instead.
- Keep `.docs/security.md` to its schema: the application's version, component security status, vulnerabilities and advisories with remediation, accepted exceptions, evidence, and history, citing `.docs/stack.md` for versions.
- Keep `README.md` a concise entrypoint with verified setup, commands, architecture summary, and links, and `.readme/` for durable operational, architectural, tooling, setup, and troubleshooting detail, never task narration or values that go stale, such as hashes, observed versions, or dates.
- Keep the English frontmatter keys and section headings of `.docs/design.md`, which follow the DESIGN.md format, and reference pending work from any document only by identifier, label, and link, never its detail or state.
- Place documentation in `.readme/` unless an established location, package boundary, or tool owns it, leave third-party and generated documentation in its own structure, and name each `.readme/` file with a unique numeric prefix and its domain, never reusing a prefix; project-owned documents take prefixes below `90`.
- Create a root `LICENSE` only on request, with the approved license.
- Update upstream intent first (`.docs/product.md`, `.docs/design.md`), then `.docs/stack.md`, then `.docs/plan.md`, then the delivered records (`.docs/coverage.md`, `.docs/bugs.md`, `.docs/security.md`, `.readme/`, `README.md`), recording a pending entry before referencing it.
- Ground each claim in authoritative evidence, label planned or unverified behavior, and run the commands the documentation asserts or name those not run.
- Keep history only where a schema requires it; every other document describes the current truth.
- Report pre-existing drift outside the changed facts without modifying it, and before closing reread the affected documents and fix every discrepancy the change caused.
