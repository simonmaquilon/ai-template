# Scale of drafts with a target project

The tests and terms of the Workflow in [SKILL.md](../SKILL.md) that settle the scale of a draft with a target project; its `Scale`, `No project`, and `Apply scale` bullets stay there.

- Project changes: A draft is narrow when the surface its change touches is known, from the files, symbols, commands, routes, screens, or elements the draft names or from what inspection and the user's answers settle, and none of the following is true: it changes stored data, it changes a public contract or interface, it changes logic with more than one caller, or it changes or adds text, assets, or styles that exist, or will exist, in more than one place. Every other draft with a target project is broad, including one whose surface is still unknown. A screen or element where a symptom appears is where to start looking, not by itself the surface the change touches. Text exists in more than one place when it has, or will need, translations that change with it, or is rendered on more than one screen.
- Project review: A draft that analyzes, reviews, or diagnoses a project without authorizing a change is narrow when the surface it examines is known, from what it names or what inspection settles, and broad when it is not; a screen or element where a symptom appears is where to start, as for a change.
- Callers: A caller is production code that invokes the logic; the tests that exercise it are not callers, although the usage sweep still counts them, and a test that asserts a text is not a second place for that text.
- Public interfaces: A public contract or interface is either what the project documents as its interface in its own reference material, not in a comment on the symbol itself, or what code outside the repository is known to consume, from the project's documentation, configuration, or code, such as endpoints, events, command options, published packages, or stored formats. An exported symbol, endpoint, or event used only inside the repository is not public by that fact alone; its callers decide its scale, and one with no callers, no documentation as an interface, and no outside consumer is neither shared nor public.
- Shared styles: A style rule counts where it applies, not where the file that holds it lives: a rule that affects a single page does not exist in more than one place because its template also serves other pages.
- Reassessment: Settle the scale from a direct first reading of the project; step 10 then delegates only what that reading left unconfirmed. Whenever step 10's conclusions or the user's answers settle what the change touches, revise the scale and apply the revised one to every step it governs from then on.
